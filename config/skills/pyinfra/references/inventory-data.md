# Inventory & Data

Source: docs.pyinfra.com/en/3.x/inventory-data.html. An inventory holds **hosts, groups, data**. Hosts = targets (SSH server, container, local machine). Data attaches to hosts and groups and is read in deploys via `host.data`.

## Inventory file format

Any Python file; each **top-level list or tuple defines a group**, and the variable name is the group name. Group names cannot start with `_`.

```python
app_servers = [
    "app-1.net",
    "app-2.net",
]

db_servers = (["db-1.net", "db-2.net", "db-3.net"], {})   # tuple form: (hosts, group_data)
```

Run: `pyinfra inventory.py OPERATIONS...`

- Autogenerated group `all` contains every host.
- A host appearing in several lists belongs to all of them; operations run **per host, deduplicated, in parallel** — not per group.
- Hosts in `inventories/<name>.py` additionally get group `<name>` (e.g. `inventories/production.py` → group `production`). Files under `inventories/` are *not* auto-joined; import between them yourself.

### Host data tuples

```python
app_servers = [
    ("app-1.net", {"install_postgres": False}),
    ("db-1.net", {"install_postgres": True}),
]
```
Consumed as `host.data.get("install_postgres")`. Any connector target string is a valid host name, e.g. `"@docker/ubuntu:22.04"`; SSH tuning per host: `("ubuntu2204", {"ssh_port": 2222, "ssh_hostname": "localhost", "ssh_user": "vagrant", "_sudo": True})`.

## Function-based inventories (alpha)

Pass a module path on the CLI instead of a file:

```sh
pyinfra myproject.inventory.make_prod OPERATIONS...    # callable returning dict
pyinfra myproject.inventory:HOSTS OPERATIONS...        # module-level list/tuple
```

Callable returns `{group_name: [hosts]}` or `{group_name: ([hosts], {data})}`:

```python
def make_prod():
    return {
        "app_servers": (["app-1.net", "app-2.net"],
                        {"app_user": "myuser", "app_dir": "/opt/pyinfra"}),
        "db_servers": ["db-1.net", "db-2.net"],
    }
```

Caveats: `group_data/` is **not** loaded (no anchor file — supply data in the returned tuples or compose inside the function); loader logs an alpha warning at startup.

## Group data files (`group_data/`)

Files matching `group_data/<group_name>.py`; variables become data for every host in that group. `group_data/all.py` = defaults for every host (lowest priority).

```python
# group_data/app_servers.py
app_user = "myuser"
app_dir = "/opt/pyinfra"
```

- Directory is resolved relative to CWD (change with `--chdir`) or the inventory file's directory; alternate location via `--group-data $DIR`.
- Only for file-based inventories (see alpha note above).
- Works with any group incl. `all` and the autogenerated per-file group.

## Data hierarchy (first match wins)

1. "Override" data passed via CLI args
2. Host data in the inventory file
3. Normal group data (`group_data/<group>.py`)
4. `all` group data (`group_data/all.py`)

Inspect resolved per-host data: `pyinfra inventory.py debug-inventory`.

## Data configures connectors

Group-data variables set connection parameters, e.g. SSH:

```python
ssh_user = "ubuntu"
ssh_key = "~/.ssh/some_key"
ssh_key_password = "password for key"
```

Full key list per connector in `connectors.md`.

## Data configures global arguments

Any global argument can be defaulted from data (note leading underscore):

```python
_sudo = True
_sudo_user = "pyinfra"
```
Mid-deploy update: `host.data._sudo_user = 'apache'`. Table of all args: `global-arguments.md`.

## Environment variables → remote operations

```python
from pyinfra import config
config.INHERIT_ENV = ["SOPS_AGE_KEY_FILE", "AWS_PROFILE", "GITLAB_TOKEN"]
```
Forwarded from the controller's `os.environ`. Precedence (low → high): `config.INHERIT_ENV` < `config.ENV` (explicit dict set in deploy) < per-op `_env={...}`.

## Canonical project layout (convention, not enforced)

```
my-project/
├── inventory.py             # or inventories/{dev,prod,...}.py
├── group_data/
│   ├── all.py               # defaults for every host
│   └── <group_name>.py
├── deploy.py                # entrypoint operations
├── tasks/                   # local.include() snippets
├── templates/               # files.template() Jinja2 sources
├── files/                   # files.put() static payloads
└── my_project/              # optional own package
    ├── facts.py             # custom FactBase/ShortFactBase subclasses
    └── operations.py        # custom @operation functions
```

Only two things are auto-loaded by convention: `group_data/<group>.py` and the per-inventory-file group. Custom facts/operations are plain Python modules — import them explicitly (`from my_project.facts import SwapEnabled`); no auto-discovery. `tasks/`, `templates/`, `files/` are referenced by your own code paths only.
